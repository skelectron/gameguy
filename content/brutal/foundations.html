Foundations: Core, Memory, Collections, Strings

You will learn
  • Why game frameworks care so much about allocations
  • How to use ByteSize, Ptr<T>, Mem and PtrOwner<T>
  • How to use NativeList<T>, String8 and the BRUTAL vector types
  • How to run work in parallel with JobScheduler

A game at 60 FPS has 16.6 ms per frame. If the .NET garbage collector pauses for 5 ms in the middle of a boss fight, players notice. BRUTAL's foundation packages let you do common work, such as building lists, formatting strings and passing buffers to the GPU, without creating garbage. If any of this C# is new to you, read The GC & zero-allocation gameplay first.

Brutal.Core: sizes and pointers

ByteSize and ElementCount are small strongly-typed wrappers. They stop you from mixing up "number of bytes" and "number of items", which is the classic bug when filling GPU buffers. Ptr<T> is a typed pointer with indexing and offsets.

Brutal.Memory: unmanaged memory

Mem.AllocZeroed gives you a Span<T> over native memory. That's ideal for big chunks of data such as tile maps, particle arrays or vertex buffers, which you don't want the GC to scan.

WITH GREAT POWER

Unmanaged memory has no safety net. If you forget Mem.Free you leak memory, and if you use it after freeing you get a crash or corrupted data. Prefer owners (PtrOwner, NativeList) declared with using.

Brutal.Collections: NativeList<T>

It works like List<T> but is backed by unmanaged memory, and AsSpan() gives you direct access to the elements. A typical use is a list of entities or sprites that you rebuild every frame without making garbage.

Brutal.Strings: UTF-8 text

Native libraries such as ImGui, SDL and FreeType all use UTF-8, but C# string is UTF-16. If you keep text in UTF-8 ("..."u8 literals, String8), you avoid converting it on every call. That's why ImGui calls in BRUTAL look like ImGui.Text("Hello"u8).

Brutal.Numerics: vectors & matrices

The names (float2, float3, int2, float4x4) deliberately match shader languages, so CPU and GPU code read alike. Brutal.Maths adds Random extensions such as NextSingle(min, max), NextSinglePointInCircle and NextSingleUnit3(), which are great for particles.

Brutal.Concurrency: jobs

The estimated cost helps the scheduler balance work across threads. Good candidates for jobs are pathfinding for many units, chunk generation and particle updates.

EXERCISE: A PARTICLE BUFFER

Make a NativeList<float2> of 10,000 particle positions using random.NextSinglePointInCircle(50f). Then, 60 times in a loop, move every particle 1 unit to the right through AsSpan(). Measure the time with Stopwatch, and use GC.GetAllocatedBytesForCurrentThread() before and after the loop to check that the loop allocates 0 bytes.
