Drawing with OpenGL

You will learn
  • How to request a core-profile OpenGL 4.1 context (which also works on macOS)
  • The GPU pipeline: vertex buffer → vertex shader → rasteriser → fragment shader
  • BRUTAL's fluent shader API and vertex layouts
  • Which GL objects are IDisposable and which you delete by hand

OpenGL is the friendliest way into GPU programming, and it's where samples/Hello/HelloOpenGl.cs starts. When you're ready for explicit, modern GPU control, move on to HelloVulkan and DemoVulkan.

The pipeline in one picture

1. Ask GLFW for a GL context

Hints must be set before CreateWindow. The maintainers note: "Our OpenGL samples run on 4.1 for compatibility with macOS, but we should support up to 4.6 no problem." GLAD loads the GL function pointers from the driver. That's why the file needs AllowUnsafeBlocks.

2. Shaders, fluently

Notice the C# 11 raw string literals (""") with the u8 suffix. The GLSL source is stored as UTF-8 bytes at compile time, so nothing gets converted at runtime.

3. Vertex data and layout

A record struct made of float2 + float3 is laid out in memory exactly the way the GPU expects. The GlAttribute calls describe that layout to the GPU: location, component count, type, stride and offset.

4. The draw loop

CONTEXT LIFETIME

Every GL object belongs to a context, and the context belongs to the window. Delete or dispose GL objects before the window is destroyed. Declaring the window first with using and the program after it gets this right automatically.

Going further

  • Uniforms: program.Uniform("viewProjection"u8, view * projection) sends a matrix to the shader. See DemoTexturedQuad.cs.
  • Dynamic geometry: DemoBox2D.cs rebuilds a vertex array every frame with GlBufferUsage.DynamicDraw. That's the start of a sprite batcher (see 2D rendering).
  • Textures: TextureLoader.LoadFromFile(path), then OpenGl.TexImage2D. Use GL_NEAREST filtering for pixel art.
  • Vulkan: HelloVulkan → HelloVulkanVma → DemoVulkan (about 485 lines for a triangle, and you control everything).
