Asset pipeline & resource handles

Two halves

  • Offline (the pipeline): converts source files (.aseprite, .png, .wav, .gltf) into runtime-friendly formats such as compressed textures, packed atlases and optimised meshes. BRUTAL has the building blocks: Ktx for GPU textures, MeshOptimizer, ShaderC/Slang to precompile shaders, and ZLib.
  • Runtime (the resource manager): loads assets on demand, avoids loading the same file twice, and hands out handles.

Why handles instead of references?

  • A handle is a small, copyable value, so it fits inside an ECS component struct.
  • The cache can swap the underlying data (hot reload, streaming, quality levels) without anyone else noticing.
  • The generation counter catches use-after-free: a handle to a freed slot no longer matches.

Hot reload

Save a sprite in your pixel editor and see it change in the running game. Hot reload makes iteration much faster.

Loading screens and async

Do file reading and decoding (Brutal.Stb, Brutal.Texture) on worker threads, then upload to the GPU on the main thread. A loading screen is simply a scene that keeps rendering while this queue drains.
