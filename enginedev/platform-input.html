Platform layer & input mapping

Game code should never know whether it runs on GLFW or SDL, or whether the player is using a keyboard or a gamepad. The platform layer hides those details, and input mapping turns physical buttons into game actions.

Actions, not keys

Pressed, held, released

Gameplay needs three questions per action: did it just go down? (jump), is it down? (run), and did it just come up? (variable jump height, charge shots). You answer them by keeping this frame's state and last frame's state:

FIXED-STEP PITFALL

If a frame runs zero fixed steps, a quick tap could be lost, and if it runs two, Pressed could fire twice. Calling EndStep() after each step fixes the second problem. For the first, buffer presses (a "pressed since last step" flag that the next step consumes), or use timers like Coin Dash's jumpBuffer.
