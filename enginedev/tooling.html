Tooling: logging, debug UI & profiling

The real difference between an engine and a pile of code is its tools. Good tools make every hour of development count for more. BRUTAL gives you strong ingredients for building them.

1. Logging with categories

Categories let you filter the noise ("show only Assets warnings"). In release builds, write logs to a file in the user's data folder, so players can send them to you with bug reports.

2. Debug UI with ImGui

  • An entity inspector: click an entity and edit its components live.
  • Tuning panels: sliders for movement constants (see the ImGui lesson).
  • Cheats: god mode, teleport, spawn, time scale.
  • Toggle the whole thing with F1, and compile it out of release builds with #if DEBUG.

3. Frame profiling

Watch the worst frames, not the average. A game that averages 2 ms but spikes to 40 ms will feel worse than one that runs at a steady 10 ms. For deeper investigation, use dotnet-trace and dotnet-counters, and BRUTAL's Monitor.Host for runtime monitoring.

4. Debug drawing

An immediate-mode Debug.Line(a, b, color) / Debug.Box(rect, color) API, flushed once per frame, is incredibly useful for hitboxes, AI paths, raycasts and physics contacts. Store the lines in a NativeList and draw them with one batched draw call.

5. GPU captures

Brutal.RenderDoc (plus RenderDoc.ImGui) lets you trigger a RenderDoc capture from a button in your game, then inspect every draw call, texture and shader input. Start with samples/Demo/DemoRenderDoc.cs.

6. Toward an editor

Once you have the inspector, debug drawing, hot reload and serialisation, you're close to an editor. ImGui's docking branch, which BRUTAL binds, can lay out a scene view, a hierarchy panel, an inspector and an asset browser. NativeFileDialog provides open/save dialogs.

EXERCISE

Build an F1 overlay for Coin Dash (on GLFW + OpenGL + ImGui) with: an FPS and worst-frame display, profiler bars for Update and Render, a time-scale slider (0.1×–2×), and a "show hitboxes" toggle that uses debug drawing.
