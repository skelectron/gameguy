Project: build a mini engine on BRUTAL

You will build "Pixie", a small 2D engine:
  • An App host that owns the window, the loop and the systems
  • Input actions, a scene stack, a sprite batch, a texture cache, audio voices and a debug overlay
  • A game (Coin Dash 2) written only against Pixie's API, never calling BRUTAL directly

Project layout

The heart: App

The game side

Notice that the game never calls GLFW or OpenGL. That's the payoff of the layering from Engine architecture: you could port Pixie to SDL or Vulkan without touching CoinDash2.

Milestones

  1. M1: Loop. App opens a window and clears it to a colour, with a 60 Hz fixed step and interpolation alpha. Measure ticks per second. (main loop)
  2. M2: Input. Actions with pressed/held/released states, gamepad support and a dead zone. (platform & input)
  3. M3: Sprites. A SpriteBatch with an atlas and a pixel-perfect 320×180 target scaled by whole numbers. Aim for 10k sprites in 1 draw call. (2D rendering)
  4. M4: Scenes. Splash → Title → Play ⇄ Pause → Credits. (scenes)
  5. M5: Assets. Texture handles with a magenta fallback and PNG hot reload. (assets)
  6. M6: Audio. A voice pool, SFX and Music buses, and generated chip sounds. (physics & audio)
  7. M7: Tools. An F1 ImGui overlay with a profiler, time scale and hitbox debug drawing. (tooling)
  8. M8: Ship. Port Coin Dash, add 3 levels from text files, publish a self-contained build, and include NOTICE.txt and credits. (shipping)
STAY HONEST

After each milestone, ask yourself whether the game needed this. If it didn't, don't build it yet. Pixie should be the smallest engine that ships Coin Dash 2. Grow it with your next game, not before.

Stretch goals

  • Swap the renderer backend to Vulkan (Brutal.Vulkan + Vma) behind the same SpriteBatch API.
  • Add a tilemap editor scene with ImGui docking and NativeFileDialog.
  • Use deterministic fixed steps for input-recording replays.
  • Run ECS systems on Brutal.Concurrency jobs.
