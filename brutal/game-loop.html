Building a real game loop

You will learn
  • The structure of a game loop: input, update and render
  • Why physics and gameplay should step at a fixed rate
  • The accumulator pattern used in BRUTAL's own DemoBox2D
  • How to read held keys and turn them into movement

In BRUTAL, you own the loop. Get this right and everything else gets easier. The engine-level theory (variable vs fixed vs semi-fixed timesteps) is covered in The main loop & fixed timestep, which has a live demo. This lesson is the hands-on BRUTAL version.

The shape of every loop

The hard question is what dt should be. If you use the real time since the last frame (a variable dt), a frame hitch can make objects tunnel through walls, and the same jump reaches different heights at 30 and 144 FPS. Games that want consistent, reproducible behaviour update in fixed steps and render as fast as the display allows.

The accumulator pattern

This is exactly what BRUTAL's samples/Demo/DemoBox2D.cs does:

  • Accumulate real time as it passes.
  • Spend it in fixed 1/60 s chunks. On a 144 Hz monitor some frames do 0 updates; on a 30 Hz one, each frame does about 2.
  • Clamp the real time to 0.25 s, so a breakpoint or window drag doesn't trigger hundreds of catch-up steps (the "spiral of death").

Things to notice

  • Input is sampled once per frame and reused by every fixed step in that frame.
  • Gameplay knows nothing about frame rate. Update always receives 1/60, so the game behaves identically on every machine. This is also what makes replays and lockstep networking possible.
  • Normalising diagonal input stops the classic bug where moving diagonally is 41% faster.
  • Once you have a GL context, replace Thread.Sleep(1) with Glfw.SwapInterval(1) and window.SwapBuffers() to wait for vsync.
INTERPOLATION (NEXT LEVEL)

After the inner while loop, accumulator / STEP is a value between 0 and 1 that says how far you are between the last state and the next. If you keep the previous position and render Lerp(prev, current, alpha), movement looks smooth even on 144 Hz screens. See the engine lesson for a live demo.
