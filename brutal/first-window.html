GLFW is a small, battle-tested C library for windows, OpenGL/Vulkan contexts and input. Brutal.Glfw wraps it in idiomatic C#, with events, properties and IDisposable.

Line by line

1. Library-wide state

Glfw.Init() sets up GLFW for the whole process. If it fails, Glfw.GetError tells you why, which is often a missing display on Linux. Glfw.Terminate() sits in a finally block so it always runs.

2. The window, owned by using

Glfw.CreateWindow returns a GlfwWindow, which is IDisposable. Declaring it with using var inside Run() means it is destroyed when Run returns. That happens before the finally block terminates GLFW, so the window is destroyed while GLFW is still alive. This "dispose in reverse order of creation" pattern appears in every BRUTAL sample. It is covered in depth in IDisposable & resource lifetime.

3. Events instead of polling

window.OnKey is an ordinary C# event. The handler receives:

ParameterTypeMeaning
handleGlfwWindowThe window that got the key
keyGlfwKeyLayout-independent key, e.g. GlfwKey.W, GlfwKey.Left
scanCodeintPlatform-specific physical key code
actionGlfwKeyActionPress, Release or Repeat
modsGlfwModifierShift, Ctrl, Alt and Super flags

Events only fire inside Glfw.PollEvents(). If you stop calling it, the OS will report your window as "Not Responding".

GOTCHA: CLIENT API

This window has no graphics context yet. To draw with OpenGL you'll add WindowHint calls before creating the window. For Vulkan you tell GLFW not to create a GL context. Both are covered in Drawing with OpenGL.
