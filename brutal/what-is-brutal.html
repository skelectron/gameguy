What BRUTAL is (and isn't)

You will learn
  • What BRUTAL is and who makes it
  • The difference between a framework and an engine
  • Which real games use it, and why studios choose it

BRUTAL is a free, open-source C# framework for making games, or for making your own game engine. It comes from Ahwoo Limited and RocketWerkz, the studios led by Dean Hall (creator of DayZ), and its source was released publicly in October 2026.

The README says it plainly: there is "no editor, no scene graph and no renderer, and we're not adding them." That isn't a missing feature. It is the whole point of BRUTAL.

Framework, not engine

An engine such as Unity or Godot owns your program. It runs the main loop, decides how objects are stored, renders the scene, and calls your scripts at the moments it chooses.

A framework such as BRUTAL works the other way round. You write Main, you own the loop, and you call into well-made libraries for the hard parts: opening a window, talking to the GPU, physics, audio and so on.

What's inside

BRUTAL is a set of small libraries, and each top-level folder in the repo is shipped as its own NuGet package (Ahwoo.Brutal.*). They fall into a few groups:

  • Foundations: Core, Memory, Collections, Strings, Numerics, Maths, Concurrency, Logging and Localization. These are allocation-aware building blocks.
  • Interop: a custom interop layer that gives C# direct, fast access to native C/C++ APIs.
  • Windowing & input: GLFW and SDL3, plus SDL's image, mixer and TTF add-ons.
  • Graphics: Vulkan (with VMA), OpenGL, ShaderC/Slang shader compilers, textures (KTX, STB, GLI), glTF, MeshOptimizer and FreeType.
  • UI & tools: Dear ImGui (docking branch), ImPlot, RenderDoc integration and a runtime monitor.
  • Physics, audio & networking: Box2D, Jolt, OpenAL, FMOD and RakNet.

Who uses it?

BRUTAL isn't a toy. It already runs real, shipping projects:

  • Kitten Space Agency (RocketWerkz) is built directly on BRUTAL.
  • RimWorld: Ludeon Studios built their in-house Waylith engine on top of it.
  • Torpedia, Art of the Rail, Gruntz and Afterskies also use it.

Why learn with BRUTAL?

  1. No hidden magic. You write the game loop, so you understand it.
  2. Modern C#. It uses .NET 10, Span<T>, unmanaged memory and UTF-8 strings, which are real performance skills.
  3. No lock-in. You can swap or skip any package. The maintainers even say math libraries "should be picked by the developer, not the framework."
  4. Engine-builder skills. Everything you build here carries straight into the Engine Development track.
HONEST TRADE-OFFS

BRUTAL has no visual editor, no level editor and no asset browser. Building from source is still "coming", so for now you use the NuGet packages. It suits programmers who like control. If you want to drag sprites into a scene, have a look at Godot or GameMaker too.

The license in one paragraph

BRUTAL uses the BRUTAL License v1.0, which is MIT-based with an added attribution clause. You can use it for free in commercial games with no royalties. If you ship a game (a "Product"), you must show the copyright notice in your credits, show the BRUTAL logo before gameplay, and include NOTICE.txt with the game. The logo requirement is waived for non-profit projects. All the details are in the Shipping lesson.
