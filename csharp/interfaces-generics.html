Interfaces, generics & inheritance

Interfaces: "can do" contracts

You've already used one: IJob from BRUTAL's job system is an interface with a single Run() method. The scheduler can run any class that implements it.

Inheritance: use sparingly

THE DEEP HIERARCHY TRAP

Entity → Character → Enemy → FlyingEnemy → FlyingShootingEnemy… and then design asks for a swimming shooting enemy. Deep inheritance trees break down quickly in games. Prefer composition, where an entity has components, and keep inheritance one level deep, for things like scenes or states. See Entities: OOP, components & ECS.

Generics: write it once, type-safe

Common constraints are where T : struct, class, unmanaged (no references inside, so it's safe to copy to native memory), new(), and ISomeInterface. BRUTAL's NativeList<T> and Mem.AllocZeroed<T> need unmanaged types, because native memory can't hold GC references.
