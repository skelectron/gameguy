Unsafe code, pointers & native interop

Game frameworks spend their lives talking to C libraries such as GLFW, SDL, Vulkan, Box2D and ImGui. C# has first-class tools for this. You'll see unsafe blocks in BRUTAL samples, so here's what they mean.

Enabling unsafe code

Pointers

BRUTAL wraps raw pointers in Ptr<T>, which provides .Value, indexing and .Offset(n), and in owners such as PtrOwner<T>.

Passing structs by address

P/Invoke: calling C from C#

Bindings such as Brutal.Glfw contain thousands of these declarations, mostly generated from the C headers (look for Generated/ folders and *.gen.cs files in the repo). Hand-written Manual/ code then adds friendly C# APIs on top: events, properties, IDisposable and enums.

Blittable types: the key to fast interop

A struct is blittable when its memory layout is identical in C# and C: only primitives and other blittable structs, with no references. Blittable data crosses the boundary with zero copying. That's why float2, SdlFRect and your record struct Vertex(float2, float3) can be handed straight to the GPU. It's also why generic native containers use the unmanaged constraint.

Native callbacks like this are how GLFW key presses become BRUTAL's window.OnKey event. Exceptions must never leak out of an [UnmanagedCallersOnly] method, which is why BRUTAL catches them and stores them in an aggregator.

SAFETY CHECKLIST
  • Never keep a pointer to a fixed or stackalloc buffer after its scope ends.
  • Every native allocation needs exactly one free.
  • Use Span<T> APIs where possible, because they're bounds-checked. Drop down to pointers only at the boundary.
