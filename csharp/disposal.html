IDisposable, using & resource lifetime

The GC cleans up memory, but not windows, GPU buffers, audio devices, file handles or native allocations. Those need deterministic cleanup, which means releasing them at a known moment and in the right order. C# handles this with IDisposable.

The pattern

using declarations

A using var is disposed at the end of the enclosing scope, even if an exception is thrown. Several of them are disposed in reverse order of declaration, and BRUTAL relies on that everywhere.

Dependency order: the BRUTAL rule

From DemoSdl.cs: "Declared in dependency order, so the using declarations dispose them in reverse when Run returns." If B depends on A, declare A first:

  • GL objects must be deleted while the context exists, so you declare the window before the program.
  • Process-wide state (Glfw.Init/Terminate) wraps everything in try/finally, and the disposable objects live inside a Run() method. That way they're all gone before Terminate runs.
  • Some handles, such as OpenGL vertex arrays and OpenAL sources, aren't IDisposable in BRUTAL. The samples delete them by hand at the end of Run.

Finalizers: the safety net (avoid it)

A finalizer (~Texture()) runs on the GC's thread at some unknown time. GPU and windowing APIs usually must be called from the main thread, so finalizers are the wrong place to release them. Use Dispose, and in debug builds log a warning if something was never disposed.
